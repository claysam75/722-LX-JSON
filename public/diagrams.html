Vessel presets

Extra scenes accepted only by Target: VESSEL. Each preset fires a sequence of 5 OSC messages — one per area (SD, MD, name 1, name 2, LD) — reusing the existing ChamSys playbacks. Addresses live in VESSEL_SCENE_OSC in constants.js; the gap between messages is VESSEL_SCENE_OSC_GAP_MS (100 ms). Empty slots are skipped; a preset with no addresses logs a warning and sends nothing.

POST /colour & /intensity

Body: { Target, Subzone, Colour } or { Target, Subzone, Intensity }. Subzone 0 = all zones, 1–4 = individual. Colour 1–20; Intensity 100 / 75 / 50 / 25 / 0. Setting every intensity to 0 sets State = OFF, otherwise ON.

Target Exec page Colour (zone 1) Intensity (zone 1) Side effects
POOL3/exec/3/2–21/exec/3/23–27—
WHIRLPOOL4/exec/4/2–21/exec/4/23–27—
YACHT NAME5/exec/5/2–21/exec/5/23–27Re-asserted when the guest entrance opens
UNDERWATER ALL6/exec/6/2–21/exec/6/23–27—
SUN DECK EXTERIOR FWD7/exec/7/2–21/exec/7/23–27Colours 5 & 6 swapped on this page
MAIN DECK EXTERIOR AFT8/exec/8/2–21/exec/8/23–27—
LOWER DECK WET AREA9/exec/9/2–21/exec/9/23–27→ syncLdDoorSpots
Subzone offset: each zone is +42 addresses from the previous (z1=2, z2=44, z3=86, z4=128, all-zones=170).
Intensity within a zone: 0%=base, 25%=+1, 50%=+2, 75%=+3, 100%=+4.
Colour and intensity executors on the ChamSys are toggles: firing one that is already active deactivates it. When a request repeats the value already stored for that zone, the executor is fired twice (deactivate → activate) so the value is re-applied to every fixture in the zone.

Guest Entrance door (backend: HULL DOOR)

Set via POST /set · HULL DOOR · State: OPEN or CLOSED. Drives the GUEST ENTRANCE name light: ON when the door opens, OFF when it closes. The door state is answered to the client before the light logic runs.
flowchart TD A["POST /set · HULL DOOR"] --> B{State OPEN or CLOSED?} B -->|no| ERR["400 error"] B -->|yes| SAVE["setState HULL DOOR = State\nbroadcast · respond 200"] SAVE --> BRANCH{State?} BRANCH -->|OPEN| GON["lights.GUEST ENTRANCE = ON\nOSC → /exec/2/38"] GON --> RESYNC["resyncYachtNameColours()\nre-fire stored YACHT NAME colours (×2)\nso the guest entrance name matches"] BRANCH -->|CLOSED| GOFF["lights.GUEST ENTRANCE = OFF\nOSC → /exec/2/37"] RESYNC --> DONE["setState YACHT NAME\nbroadcast · feedback push"] GOFF --> DONE
resyncYachtNameColours: if all four YACHT NAME subzones hold the same colour, one all-zones colour executor is fired (deactivate → activate); otherwise each set subzone is re-asserted individually. Nothing is sent if no colour is stored.
The door change does not call syncLdDoorSpots. LD Door Spots only re-evaluate on the next LOWER DECK WET AREA scene / colour / intensity request.

Yacht Name lights

Three light groups under YACHT NAME.Lights: UD SB (upper deck stbd name → /t/name/side), HULL DOOR (aft name → /t/name/aft) and GUEST ENTRANCE (side guest entrance name → /t/name/guest, also driven by the door).

LD Door Spots

Spots on the inside surface of the guest entrance door. ON only when the door is OPEN and the LD Wet Area has any active state.

syncLdDoorSpots() is called from:

POST /scene · LOWER DECK WET AREA POST /colour · LOWER DECK WET AREA POST /intensity · LOWER DECK WET AREA

If LD Door Spots appear stuck ON after the door closes, check the Guest Entrance card on the control page — if it still shows OPEN, the sensor hasn't sent the CLOSED update. Use its Closed button to force it, then re-send any LOWER DECK WET AREA scene to re-evaluate.
